## Smallest implementation that delivers the cases

1. **Capture only answers that change the outcome.** Keep the one-screen finder, optional league class and existing age/goal controls. Club and advanced adult Balanced can take the preferred hybrid directly. For competitive teenagers choosing Spin, add one conditional way to identify an existing full bed of round polyester, including “I’m not sure”. Reuse an explicitly selected saved racket setup when its component identities are known. Allow optional known tension in its original unit. A visitor without a saved racket must also be able to reach the case. Avoid bringing back a required product search or weekly frequency.
2. **Represent the age boundary honestly.** One small option is to split the visible 13–17 choice into 13–14 and 15–17, keeping both in the existing older-junior rules. Accept the existing API `13_to_17`, `junior_26` and `junior_full_size` inputs. A legacy band or racket size cannot establish that a player is over 14. Preserve the existing tension behaviour when age is unknown. Extend request validation and generated types for the new distinctions. Keep finder answers transient.
3. **Choose the setup family before scoring stock.** Put the confirmed adult Balanced rule ahead of the old comparison in both the store’s hybrid-inventory gate and the selector. Assign polyester to mains and synthetic gut to crosses. For the qualified junior Spin case, rank full-bed polyester by suitability for the requested change. With a known current product, use a higher editorial comfort rating as evidence of “softer”, then rank eligible options for spin. The replacement can be round or shaped. If the player knows only the construction, a proposed starting rule is to use the existing junior high-comfort band (4–5/5) and rank those candidates by spin. Label this as an editorial match and review the cutoff against David’s examples. Use the existing gauge, price and stable-ID tie-breaks after suitability. Preserve other goals, sports, and the existing current-poly Comfort and current-multifilament Control paths. [Scoring](../../backend/internal/marketplace/recommendations.go)
4. **Choose a tension after the setup is known.** Honour an explicit request for stringer help. Keep a valid stated tension in its original unit. For the junior Spin exception with unknown tension, return pending. Otherwise use 48 lb for confirmed ages 15+ under the tennis default, subject to the service and any supplied racket limits. If the target is outside those limits, leave tension pending and explain why. Do not silently substitute 22 kg or clamp the number. A 48 lb booking uses `4800` in both centi-lb fields, zero in both centi-kg fields, and `tension_pending: false`. Use the existing unit helpers to display and apply it, then confirm it survives draft restoration and quoting.
5. **Return a bookable result and explain the choice.** Use the existing full-bed and hybrid stock pools, `priceComponents`, four-knot checks, and combined portion availability. Try the next suitable pair when one fails a stock check. Surface unexpected store errors. Proposed fallback for adult Balanced when the preferred hybrid is unavailable is the existing eligible full-bed comparison, with a brief explanation of the missing cross or unavailable service. For the junior, if stock cannot support the requested softer Spin change, use the established soft full-bed fallback or stringer review and label the trade-off. These fallback orders are implementation proposals. Show the leading hybrid immediately, with its two roles, exact tension or pending state, and labour-inclusive estimate. Keep the existing cap of three.
6. **Update the contract and tests together.** Extend the existing Go request, `ValidateRecommendation` and schema generator, then regenerate `api/openapi.json` and `frontend/src/lib/marketplace-contract.d.ts`.
